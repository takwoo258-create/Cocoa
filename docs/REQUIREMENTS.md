# Cocoa 项目需求摘要（脱敏版）

> 本文是项目原始需求书 `build.md` 的**脱敏摘要**，供仓库读者理解产品目标与验收口径。
> 已删除：服务器 IP/SSH 凭据、GitHub 个人访问令牌、邮箱等敏感信息。
> 原始文件保留在仓库外，不参与版本控制。

项目定位：Sand Salt 团队开发的虚拟智能体陪伴系统 —— 用户自配模型、自建角色，角色拥有独立人设、记忆、状态、作息与创作能力，并通过 QQ 与 App 双通道陪伴。

---

## 一、基础服务

1. **模型接入**：兼容 OpenAI 协议；API Key 与 Base URL 在应用内录入（不配置不可用）；支持拉取模型列表、测试连接，并以 SVG 图标标注文本/图片/语音三种模态能力。
2. **多模态分流**：优先级 语音 = 图片 > 文字；图片/语音先由模型转成文字描述，再与用户文本合并送入主模型。
3. **上下文窗口**：按模型上下文上限计算占用；陪伴主页不显示，调试模式下以环形进度条 + 百分比显示在输入框下方；接近 85% 时，若智能体在回复则等回复结束再做压缩，压缩期间用户输入入队并提示「在回味之前的记忆喵~」。
4. **记忆系统**：接入 Embedding 模型；后台另起会话推理用户的爱好、特长、雷点、少见偏好等特征，结合嵌入形成记忆点；记忆点构成「智能体 → 大类目 → 小类目 → 记忆点」的神经网图，节点颜色区分层级、记忆点恒为白色、亮度 = 权重、相关记忆用虚线连接；点击智能体/类目展开折叠，点击记忆点在下方展开详情（创建时间、大小类目、内容、关联）。记忆页为独立页面，模型可调取记忆回复。
5. **语音**：STT 使用 xiaomi Mimo 开放接口，TTS 使用 Breeze TTS 2 接口。
6. **人物画像**：满 200 次对话或距上次画像满 3 个自然日后，在新会话中生成画像，二次投送模型提炼心理与行为特征，结合嵌入写入记忆，并与上一版差异对比写入 changelog；完成后清零计数。处理画像期间对用户的回应方式与压缩上下文时一致。

## 二、亲昵陪伴

1. **人设配置**：姓名、年龄、种族、性别、性格、世界观、爱好、与本人关系、外观、职业；顶部「便捷输入」把模糊词送给大模型扩写润色并以 JSON 回填。
2. **多角色**：记忆、人设、资产相互独立；新角色可沿用旧模板。
3. **思考模式**：默认关闭；用户说「你再仔细想一想」等明确要求时开启，或设置-智能体-对话中开启。
4. **句子完整性判定**：文字先交给模型判断（强制关闭思考，只允许返回 `yes`/`no`，无标点）；`no` 时等 30 秒，期间无新消息则生成回复；`yes` 直接回复。
5. **回复风格**：口语化、简短，按用户语句类型（陈述/疑问）简洁回应。
6. **回复 JSON 协议**：
   - 无分段：`agent[num]`、`type:"message"`、`content`
   - 有分段：`devide[num]`、`wait[num]`（秒，0–8）、`agent[num]`
   - `type` 取值：`profile`（人物画像）/ `message`（回复）；仅智能体对话允许分段。
7. **角色状态**：每 10 分钟结合人设与世界状态刷新，返回 `type:"status", motion, psychology, mood, health`；动作行为用大写号。
8. **健康状态**：依据种族、性别与设定推导生理状态、健康程度与疾病。
9. **外部信息**：调用微博热搜接口或 RSS 订阅，挑选若干热点阅读并生成感想，记录写入「书架」并进入当日上下文；该上下文最多保留 3 天。
10. **自主创作**：按当天聊天、用户态度、阅读的新闻、角色状态写日记；小说不限题材字数，但不得含色情、暴力、诱导未成年人等不良内容，政治敏感内容需变相表述。
11. **书架**：独立页面，收纳小说、文集、浏览记录、日记本；日记需六位随机密码（每日更换），角色只能暗示线索、永不直接告知。
12. **网页搜索**：通过 search/fetch 接口；若用户已配置 DeepSeek 模型则复用其 API Key，否则单独询问。
13. **主动回复**：模型发出消息后进入 60–80 秒随机等待期；超时由模型判断是否继续追问，不追问则结束本轮并生成下一条主动消息；JSON：`type:"subjective", content, sendsec`（UTC+8 语义）。
14. **作息**：午睡/夜间睡眠时提示「<角色名>在休息哦，要稍后再来找他/她吧」/「夜深了，明天再来找他/她吧，你也要早点睡哦」，且每句追加「若强行叫醒的话，可能会带来不必要的麻烦哦」；用户消息可触发模型判断 `wakeup:0`（不调整不回复）/`wakeup:1`（调整状态并回复）。

## 三、信息存储

会话等元信息用 SQLite；创作、会话正文、人格设定等文本经多重对称加密后存服务器本地；角色与角色、用户与用户之间数据完全隔离、互不共享。

## 四、会话管理

用户与角色的对话为主会话；后台系统行为（状态刷新等）会新建会话但非每次；上下文满时新建（主会话满后不再新建）。

## 五、多用户

1. 仅邮箱注册登录；注册需验证码 + 二次确认密码；登录支持用户名/邮箱 + 验证码/密码。
2. 用户间 API Key、角色设定等个人配置独立；对接 QQ 时共用同一机器人号（同一 WebSocket 地址）。
3. 注册需填 QQ 号，后台校验 OneBot 返回的 QQ 是否在注册名单：不在 → 「账号未注册，花名册上没有主人的大名哦~」；在但缺配置 → 「<未配置项目名>还未设置哦，请前往 Cocoa 进行配置」。

## 六、统计信息

**普通用户**
1. Token 消耗（当日/近三天/近七天/近一月/近一年/全部/自定义；分支显示输入命中、输入未命中、输出）、消费金额、按模型筛选；柱形图可视化，点击柱条弹出详情浮窗。
2. 陪伴天数（爱心大 Banner）与亲密度指数 0–100（模型判定，折线图）。
3. 角色对话数、创作文集数、健康状况异常次数、心情状态异常次数（由模型判定）。

**超级管理员**
4. 注册用户数、在线用户数（10 分钟内对话）、用户活跃指数（自定义算法）。
5. Token 消耗/消费/调用汇总，可按单用户筛选。
6. 总会话数、活跃（有效）会话数、全部会话与详细列表。
7. 存储用量：数据库、消息文件、缓存（未来会被清除的）。

## 七、配置

**普通用户**：服务配置（各模型）；个人信息（用户名/邮箱/密码/QQ）；角色配置（设定、RSS、创作标签与频率）；模型分工（主会话、创作、梦境等任务分别用哪个模型）；Token 限额——硬限额（达限额停主会话与创作、停所有角色服务，并向用户发消息）与软限额（停创作与新闻阅读，仅保留会话与状态更新，状态刷新降为 4 小时一次，并提示用户）。

**超级管理员**：邮箱服务配置、用户管理、日志审计、OneBot API 配置。

## 八、客户端

Flutter，仅 Android；保持登录态；覆盖普通用户与超级管理员功能；不开发独立应用对话。

## 九、工程约束（原始要求摘录）

1. 服务器资源紧张（4G 级），命令执行不得把机器打挂。
2. 冒烟测试通过不代表 Android 端无 bug，需真机/模拟器验证。
3. 更新日志写在 `update<ver>.md`：`+` 新增、`-` 删除、`±` 调整。
4. 有疑问及时沟通。
5. 当前具备完全权限，注意不要造成数据丢失。
6. 开源协议 GPL v3；APK 通过 GitHub Release 投递；仓库需及时更新。
7. 只接入 QQ，机器人框架 NapCat 已在部署，只需实现接口（本地实测服务器未装 NapCat，需自行部署）。
8. 交付后端部署代码与可安装 APK。
9. 后端部署在指定服务器（凭据不进仓库，见 `docs/DEPLOY.md` 的部署流程）。
